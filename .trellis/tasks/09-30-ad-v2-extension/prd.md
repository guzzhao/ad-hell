# 广告演示 v2：可扩展架构 · 真实感素材 · 摇一摇跳转 · 来电广告

本任务承接 `09-30-phone-ad-chaos`（v1 已落地并提交 `7466cde`）。
v1 的 PRD 仍是本任务的上位约束，本文件只记录 v2 新增与变更的内容。
技术设计见 `design.md`，执行清单见 `implement.md`。

## Goal

在 v1 演示页之上建立**可扩展架构**，使后续新增广告形态、呈现面、触发方式、媒体类型
只需"注册"而不必改动既有实现；并以此架构落地第一批新功能：

1. **真实感素材** —— 广告观感相对 v1 的纯色块 + 文案明显提升
2. **摇一摇跳转广告** —— 模仿现实中"摇动手机即跳转"的滥用行为
3. **来电接听页广告** —— 一个全屏接管、有真实听感通话音的来电界面

用户价值：让"广告不只弹窗，还会伸手去够你的传感器和喇叭"这一层现实也被演示出来，
同时把这张演示页从"一次性作品"变成"能持续加功能的作品"。

## Background

### 需求原话

> 架构要设计好，后面会增加多个功能，比如添加真实广告、模仿摇动手机跳转广告、
> 广告是一个电话接听页面、有真实的通话音

### 由现状推导的架构缺口

| 缺口 | 直接后果 |
|---|---|
| G1 · 渲染分派不可扩展 | 新增广告形态要改 `AdPopup.vue` 的常量表，属于"改既有代码"而非"注册" |
| G2 · 触发器只有时间一种 | 摇一摇是**外部事件**驱动的，塞进 `advance(dt)` 会破坏"同输入同输出" |
| G3 · 覆盖层是布尔量 | 来电广告、假落地页与将来的全屏广告会互相踩状态 |
| G4 · 素材无媒体维度 | `AdCreative` 只有文案与调色板，装不下图片 / 视频 / 音频 |
| G5 · 无音频子系统 | 自动播放策略、静音开关、多路音频互斥都无处安放 |
| G6 · 无能力探测 | 桌面无加速度计、iOS 需授权、音频可能被策略拦截——都需要显式判断 |

## Requirements

> 编号沿用 v1 的 R 序列，v2 从 R11 起。

- **R11 · 可扩展架构。** 广告**形态**、**呈现面**、**触发方式**、**媒体类型**四者均须可注册扩展：
  - 新增一种时只新增文件 + 在注册表加一行，**不改既有形态 / 呈现面 / 触发的实现文件**；
  - 漏注册必须是**编译期错误**（`Record<Union, T>` 穷尽性）或**测试失败**，而不是运行期惊喜。
- **R12 · 真实感素材。** 广告观感相对 v1 明显提升，但**不引入任何二进制资源文件**：
  素材仍由程序生成（CSS / SVG / Canvas），同时在数据结构上预留 `media` 描述符与资源清单，
  使真实文件将来可直接放入 `public/media/` 并登记一行即可替换，渲染层零改动。
- **R13 · 摇一摇跳转。** 支持"摇动设备即跳转"这一滥用行为：
  - 摇一摇是**素材的能力位**，只在屏幕上存在带该能力的广告时生效；屏上没有时摇动**毫无反应**；
  - **一次摇动只产生一次跳转**（窗口累积 + 每实例冷却两层防抖）；
  - 跳转沿用 R3：只在页内，绝不真实外链；后果与误触关闭键同罪（追加 2~4 个弹窗）；
  - 无传感器或未授权的环境须有等价演示路径，且**拒绝授权不是错误路径**。
- **R14 · 来电接听页广告。** 一个**全屏接管**的来电接听界面作为广告：
  - 覆盖手机内全部弹窗；可关闭 / 不可关闭等变体沿用既有 `CloseVariant`，不新造关闭语义；
  - 由**固定剧本节拍**上演，不依赖随机生成，保证每次都能被验收；
  - 有**硬性时长上限**，即使是无关闭键的变体也必然自动结束——接管不等于困住用户。
- **R15 · 通话音。** 来电广告播放**有真实听感的通话音**，由 **Web Audio API 程序合成**
  （振铃 + 通话中的人声频段质感），不引入任何音频文件。
  音频必须可被用户一键静音，且不得在用户未交互前自动播放。
- **R16 · 音频与传感器合规。** 音频播放与传感器授权前须有明确提示；不得真实外链；
  不得真实调用或伪装真实拨号；`prefers-reduced-motion` 与"静音"偏好都须被尊重，
  且两者**不得互相推导**（动效偏好不蕴含声音偏好）。
- **R17 · 回归不退化。** v1 的 R1–R10 与 AC1–AC11 仍然成立；F10 的 63 个单测全部保持通过；
  逃生通道在任何新形态下都保持可用。

## Acceptance Criteria

| # | 对应需求 | 可观察结果 |
|---|---|---|
| AC12 | R11 | 新增一种 `AdLayout` / `AdSurface` 而不注册 → `npm run type-check` **直接报错**；新增素材引用未定义的 `mediaId` 或未实现的 `trigger.kind` → `registry.spec.ts` 失败 |
| AC13 | R12 | 广告素材明显比 v1 有质感（有层次的光影 / 图形 / 动效）；`dist/` 内不新增二进制资源；替换某素材的媒体只需改资源清单 |
| AC14 | R13 | ① 屏上有摇一摇素材时，摇动该设备触发一次页内跳转并追加 2~4 个弹窗；② 冷却期内连续摇动不叠加；③ 屏上**没有**该类素材时摇动毫无反应；④ 桌面无传感器时可用等价操作触发同样效果；⑤ iOS 拒绝授权后页面照常可用、不报错；⑥ 全程无真实外链 |

| AC16 | R15 | 来电广告出现时可听到通话音；一键静音后**立即**静音；用户尚未交互时不出声，改显示「点击开启声音」 |
| AC17 | R16 | `AudioContext` 不存在、`DeviceMotionEvent` 不存在、或传感器授权被拒时，页面功能降级但**不报错、不卡死、无未捕获异常** |
| AC18 | R17 | 五项质量门全绿；63 个既有单测全部保持通过；v1 的 AC1–AC11 人工核对项无退化 |

## Decisions

- **D1 · 素材策略（原 Q1）。** 采取「抽象层先行、内容仍程序生成」：
  `AdCreative` 增加可选 `media` 描述符并配一份资源清单；v2 的广告画面与通话音**全部程序生成**，
  零二进制资源。真实素材将来只需放入 `public/media/` 并登记清单即可替换，组件不改。
  **v1 的 R6 合规红线不豁免**：品牌名与文案仍须自创。
- **D2 · 无传感器 / 未授权环境的降级。** 真实传感器优先，另有显式降级控件：
  手机有传感器时走真实 `devicemotion`；iOS 13+ 需在用户手势内请求授权，
  届时应显示「允许访问运动与方向」按钮（这个要权限的动作本身就是演示的一部分）；
  桌面无加速度计时改为在手机区域内快速甩动指针；任意环境都保留一个可点的兜底入口。
- **D3 · 摇一摇的触发范围。** 绑定到具体广告素材，**不是**全局劫持：
  只有屏幕上正存在带 `trigger: { kind: 'shake' }` 的广告时才响应，
  一次摇动只算一次（防抖 + 冷却）。
- **D4 · 来电广告与 `fakeCall` 素材的关系。** 两者并存，不合并：
  `AdFakeCall` 是"伪装来电的小弹窗"（R2 已覆盖的既有素材）；
  R14 要的是"全屏接管 + 有声"的**来电接听页**，是另一种呈现面。理由见 `design.md` §3.2。

## Out of Scope

- 不接入真实广告 SDK、后端服务或任何数据上报（沿用 v1）。
- 不做真实外链跳转、不真实拨打任何号码、不伪造扣款或公安类恐吓内容（沿用 v1 与 v1 design §6）。
- 不引入任何二进制资源文件（D1）；不引入音频库（如 Howler / tone.js）与动画库。
- 不把 `landingOpen` 泛化成覆盖层栈——当前只有一个实例，抽象度不划算；
  改造条件已写进 `design.md` §3.3 的注释。
- 不做 E2E 与视觉回归测试（沿用 v1）；真实发声与真机甩动的体感由人工核对清单覆盖。
- 除 `.trellis/` 内的任务与规范文件外，不改动 Trellis 脚手架本身。

## Technical Notes

- 平台为 DeepSeek Harness，属 Trellis **inline 模式**：不配置 `implement.jsonl` / `check.jsonl`，
  Phase 2 通过 `trellis-before-dev` 加载规范。
- 质量门与前端约定见 `.trellis/spec/frontend/`；v1 的技术设计见
  `.trellis/tasks/09-30-phone-ad-chaos/design.md`，本任务的设计在此基础上演进。
- **必须守住的三条不变量**（详见 `design.md` §0）：
  ① 引擎保持纯函数、不 import 框架；② 风暴由种子 + 固定剧本决定，可复现；
  ③ 逃生通道永远可用。传感器与音频只能作为边缘适配器存在，
  否则 v1 建立的"可单测"优势会丢失。
- **最高风险改动**：`coverageEstimate` 必须排除 `takeover` 实例。
  一个全屏接管实例贡献 100% 覆盖率；若节拍上演时屏上已有 ≥14 个弹窗，
  崩塌会被这个**剧本实例提前触发**，崩塌时机就不再由风暴本身决定（`design.md` §5.3）。
